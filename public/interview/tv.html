CK / Interview guide

Thinnava

A social food memory app: your friends' food experiences, organised. Android app plus website.

30-second pitch

Thinnava, Telugu for "Did you eat?", is a social food memory app. You connect with people you actually know, log your own visits, and privately save what friends tell you or what you find online. The trick is the import: you copy a WhatsApp message, tap Read it, and AI fills the form with the place, dishes, rating and price, and you confirm. Privacy is enforced in the database, not the app. It's an IISc course project with a team of two. Release 0.1.0 shipped on 25 October 2026 as an APK and a website.

2-minute walkthrough

  • Three kinds of entry: My visit (posted to chosen audience lists), Friend reviewed (private), Internet suggested (private), plus connections' own posts.
  • One rating scale everywhere: Good / Okayish / Bad, optional price per person. No photos, no star scores, no influencer feed. Friends' experiences, not strangers' ratings.
  • Connections are mutual and request-based. Audience lists work like Snapchat: All connections, Only me, or custom lists.
  • Companion tags work like Instagram collabs: accepting a tag means adding your own review.
  • Home timeline, place page ("who's been here"), map with layers, wishlist, and one-tap hand-offs to Google Maps directions and Swiggy.
  • Works offline for manual entries via an outbox that syncs later.

Architecture and stack

Expo / React Native app (TypeScript, Expo Router, TanStack Query, MMKV outbox)
   -> HTTPS (supabase-js, JWT)
Supabase: Postgres + Row Level Security + RPCs, Google Auth,
          Edge Functions (Deno), pg_net push trigger, pg_cron
   -> Gemini (extraction), Ola Maps + OpenStreetMap (places), Expo Push
  • Same Expo app runs on react-native-web and is exported as a static site, so iPhone and laptop users get the same account and data.
  • Map is MapLibre with free OpenFreeMap tiles, with supercluster for grouping pins.
  • Client-generated UUIDs make offline creates idempotent. Platform-specific code is isolated in src/platform/ so the code stays web-compatible.

Hard problems and what I learned

  • WhatsApp does not share text to other apps cleanly. Solved with a copy-then-Read-it flow and a "Use copied text?" paste route, plus an Android share target for apps that allow it. On web, a Paste a message button replaces automatic clipboard detection since browsers need permission.
  • Free-tier limits are real. gemini-3.5-flash allowed only 20 requests a day per project (measured), so the default is the Flash-Lite model with a separate fallback allowance.
  • Privacy review found issues. A security review on 2026-10-18 led to fixes such as revoking default public execute grants on functions and restricting link schemes to http/https.
  • Instagram and YouTube links cannot be read server-side. The app keeps the link and offers to paste the caption instead.
  • Hand-off links break. Search URLs change, so each is a single constant to re-test before every release.
  • Android map and sheets. The map view is rendered as a texture view so bottom sheets draw above it; pins group sooner on phones because they carry wide name labels.

Limitations to state honestly

  • No iOS app; iPhone users use the website and push works only after Add to Home Screen.
  • Web has no automatic copied-message card, no offline saving yet, and no web push.
  • Free Supabase projects pause when unused, so someone must open the app weekly.
  • Gemini free tier may use prompts for training; disclosed in the privacy policy and accepted for a course demo.
  • Final name and logo are still open; Zomato and District are v2.
  • Review accuracy on extraction is 89%, which is why confirmation is mandatory.

What I would do next

  • Zomato and District hand-offs through a supported route.
  • Web push and offline writes on web; an iOS build if a paid Apple account becomes available.
  • Grow the extraction eval set with real friend messages and track review accuracy over time.
  • Move off free tiers only if the project continues beyond the course.

Likely questions

Why enforce privacy in the database?

The client is untrusted. With RLS and security-definer functions, every read goes through the same rule: connected, not blocked, and inside the audience list. The app can be buggy and still not leak. We test those rules with pgTAP.

How does the AI import work end to end?

Copied text goes to the extract Edge Function. It rate-limits, calls Gemini with a system prompt and a JSON response schema at temperature 0, validates with zod, searches OpenStreetMap for up to three place candidates per item, post-processes (dedupes dishes, nulls out-of-range prices, drops future dates) and returns. The app shows a confirmation screen with per-field confidence.

What stops the AI hallucinating?

Prompt rules (never invent; a dish counts only if the message says how it was), a strict schema with no speculative fields, zod validation, a mandatory human confirmation, and an eval set with a hard bar of zero invented dishes.

How does offline work?

Writes go to an MMKV outbox with client-generated UUIDs so retries are idempotent; reads come from a persisted TanStack Query cache. When online the outbox flushes to Supabase.

How do companion tags stay private?

A tagged person can see only the one visit they are tagged on. A friend-of-friend who is connected to the tagged person sees "B went with A" but none of A's content. Rejects are silent and blocking hides your name behind "Someone".

How did you keep it free?

No card anywhere, Supabase free plan, Cloudflare Pages, OpenFreeMap tiles, Ola Maps prepaid with no credit, Gemini from a project with no billing account, and quota gates in the database that pause a feature instead of billing.

How did you split work with a teammate?

Written two-person workflow in the spec: separate branches per person, each owning folders, tables and functions, with shared files changed only after agreement. Currently one person has been doing both halves in milestone order.

What would you change in the data model?

Possibly introduce dishes as entities for search later. They were deliberately left as free text to keep logging fast and the UI clutter-free.
